# Troubleshooting and recovery

Read `pz status`, `pz health`, `pz jobs` and `pz job JOB_ID`. Error responses use
fixed codes. Raw game/Steam logs remain private in the logs volume; `pz logs`
shows recent game diagnostics in your local terminal. Review before sharing.
Container health checks indicate control-service reachability; PZ READY comes
from ops process, generation, UDP and authenticated RCON checks.

## Initialization and storage

`INITIALIZE_DATA_FIRST`: use `pz init-empty` or import a stopped instance into a
new target. Offline tools require both control services stopped. `TARGET_NOT_EMPTY`
means the selected named data volume already contains data. Select a new project;
do not delete a persistent volume merely to get past this check.

`BUSY`: another lifecycle owner or live game holds a kernel lock. Guard files are
permanent; deleting one can break mutual exclusion. Inspect jobs and child state.
An intentionally shared app volume allows one game/Steam installation at a time.

Steam `Missing file permissions`: run the project initializer after the game is
stopped. It owns the app top directory, `steamapps`, nested Workshop mount and
other project volume roots as UID/GID 1000. It never recursively chowns the source.
Never solve this by making a service privileged.

On Windows a secret file generated by a different restricted user may need a read
ACL for your signed-in Docker Desktop user. Grant access only to that user, SYSTEM
and administrators; never make credentials world-readable. Generate normal
deployment secrets with `pz init-secrets` in your own terminal.

## Readiness and graceful stop

`STARTING_OR_DEGRADED` means a child exists but a required UDP listener or RCON
player response is missing. Ops does not kill or restart it automatically. Check
private startup/Workshop logs, version, heap, storage and required ports. Internet
failure alone does not remove READY. `READINESS_TIMEOUT` leaves the child and
pending evidence intact; it does not prove a clean stop.

`PLAYERS_CONNECTED`: disconnect clients or deliberately use `--force` for graceful
save/quit with a known occupied server. `PLAYERS_UNKNOWN` and RCON failures always
refuse the operation, including with `--force`. `STOP_TIMEOUT` never sends a kill.
The server agent attempts save/quit on container SIGTERM; Docker's outer 90-second
grace may ultimately terminate an unresponsive container. Do not describe that as
a verified clean shutdown. Avoid `docker compose restart` while busy jobs run.

## Version and Workshop

`APP_INSTALL_INCOMPLETE`: a Steam installation failed or was interrupted. Keep the
game stopped, inspect the private installation log and retry `pz install`.
Start remains blocked until a successful installer clears the marker. A changed
build requires new Linux startup version evidence before importing-world start.

`BLOCKED_VERSION`: the private imported marker requires 42.21.0 but this Steam
build has another version or lacks current Linux startup evidence. Do not change
the marker to force a test. A synthetic empty-world run may establish the current
build's version; verified evidence survives service restart and is invalidated
when the installed Steam build changes.

Workshop reports retain `Missing`, `Unknown`, `Update` and `Current`. Remote API
failure is Unknown. `workshop-update` requires a running instance and known safe
player state; it backs up, stops and performs a fresh PZ startup/download, then
returns before/after manifest evidence and unresolved items. No upstream Workshop
change triggers automatic restart by itself. READY alone does not establish every
mod's functional correctness. Check case-sensitive paths, missing scripts, Lua,
model/media errors and compare with the prior platform's baseline.

For a 6 GiB imported-world heap, measure both host free RAM and Docker memory
before starting. Leave additional room for the JVM's native allocations and host
applications. Do not infer host headroom from guest MemAvailable alone or lower
the imported-world heap merely to complete acceptance. A disposable empty test
may use a separately configured 2 GiB heap.

## Journals and interrupted jobs

An interrupted queued/running job becomes `interrupted`, sets `desired=false`
and blocks automatic work. It is never blindly replayed. Inspect its phase and
private journals, then use `pz recover` when game/data state is proven. This
command can recover an apply publication by comparing original/new INI hashes.
Unexpected third-party edits return `RECOVERY_AMBIGUOUS` and retain evidence.

Acknowledgement recovery requires the same healthy child generation that crossed
the original readiness barrier. A different generation cannot finalize pending
state using a caller-supplied hash. If that generation has been lost, preserve the
journal and restore a verified stopped backup into a new project. Keep the
interrupted target for inspection instead of deleting its journal to bypass it.

An interrupted restore retains `restore-journal.json` and staging evidence and
blocks start. Prefer restoring the original verified archive into a **new empty
project**. Replacing an interrupted partially published target automatically is
unsupported because its pre-restore safety cannot be inferred. Leave that target
offline. Archive/hash/database failures before publication leave target data
untouched.

## Mod plans and config state

Use preview before `apply-mod-plan ... --apply`. `PENDING_*` errors mean ordered
managed state or immutable plan/history provenance no longer validates. Restore
the reviewed plan and its saved before-INI from a coherent backup; never patch a
hash or count to suppress the error. Unrelated PZ config rewrites are allowed.
`config-commit` refuses active pending/apply/ack state. Only a fresh healthy start
can internally acknowledge a pending plan. Successful startup records a portable
whole-config baseline including Map in the managed fingerprint.

## Private publication boundary

Run tests, public-tree audit and staged/history inspection before pushing.
`.gitignore` is only the first layer. The scanner reports path and rule, never
matched credential values. Remove an accidental secret from all unpublished
history; rotate it if it ever reached a remote. Runtime archives, `.env`, SQLite,
tokens, app files and Workshop content never belong in Git or CI artifacts.
